## Strengths and architectural judgment

- **The writer race is removed at its cause.** `deployment/node-red/paired_gpio_daemon.py:42` restricts raw access to GPLEV0 reads and fixed paired GPSET0/GPCLR0 writes; no production userspace FSEL read/modify/write remains. `:202` exclusively reserves both lines before mapping, `:215` preloads paired HIGH, and `:216` delegates output configuration to the kernel. Normal commands at `:267` retain the existing paired mask and readback. This deliberately preserves the existing latch-write mechanism without assuming that grouped libgpiod calls produce a grouped hardware store.
- **The kernel/API reasoning fits the integration.** Independently inspected [BCM driver source](https://raw.githubusercontent.com/raspberrypi/linux/rpi-6.12.y/drivers/pinctrl/bcm/pinctrl-bcm2835.c) serializes FSEL changes with `fsel_lock`, uses per-line set callbacks and has no `set_multiple` or `gpio_request_enable` callback. The [GPIO v2 request contract](https://docs.kernel.org/userspace-api/gpio/gpio-v2-get-line-ioctl.html) supports exclusive AS_IS requests without direction flags and does not promise controlled line state after release. The [Chip](https://libgpiod.readthedocs.io/en/v2.3/python_chip.html) and [LineRequest](https://libgpiod.readthedocs.io/en/v2.3/python_line_request.html) APIs support the tuple settings and reconfiguration used here. AS_IS is a userspace request choice, not a physical safety guarantee.
- **Metadata validation binds the actual opened chip to the intended bank.** `paired_gpio_daemon.py:89` verifies the opened rdev's GPIO bus object, direct firmware node, structural parent and exact driver backlink. `:114` cross-checks the legacy gpiomem class/rdev, unique bound platform node, DT parent/addressing and bank base. `:45` rechecks gpiomem rdev after opening. Unknown/ambiguous metadata fails before reservation, with no guessed index or legacy fallback. This is a deliberately narrow profile, not kernel-version attestation or a guarantee of support for the installed Pi.
- **Lifecycle failure handling preserves the ownership boundary.** Initialization at `:191` does not serve after a failed reservation, mapping, preload, reconfiguration or readback. Cleanup at `:226` attempts DRAIN while ownership remains, closes raw access before release and retains strong references if unmapping fails. Outer cleanup at `:483` preserves the original service failure. Exceptional cleanup is best effort; process teardown order and physical release behavior are not promoted into guarantees.
- **Lighting retains independent authority.** Unchanged `src/freeze_protect/lighting/executor.py:391` requests only GPIO21; its ordinary values and close path at `:406` and `:412` stay in the kernel driver. There is no new shared controller, socket, policy state, GPIO21 raw write or light-to-shower command path. With the reviewed driver, disjoint set/clear masks do not overwrite each other's latches, and all configuration writers use kernel serialization. Unrelated raw writers remain outside that ownership guarantee and are explicitly excluded during migration.
- **Protocol and lease integration is preserved.** The full paired `SupplyLease`, request validation, socket loop and shutdown path remain consistent with protocol 2 and the 60-second lease. Unchanged `deployment/node-red/paired_gpio_client.py:34` supplies that protocol and `:66` checks matching paired receipts. `deployment/workstation-codex/freeze-protect-commission:152` continues to use the standard-library client and output/high checks; it does not acquire a competing gpiod request. The API change is confined to daemon initialization/ownership, not the existing client or restricted helper authority.
- **Delivery and rollback account for the service boundary.** The existing paired unit retains `nodered`, its gpio supplementary group, runtime directory and historical system Python. `deployment/lighting/paired-gpio-migration.conf.example:6` explicitly replaces the interpreter, supplies a dedicated environment file, closes the device policy and deliberately omits gpiochip access until inventory. `docs/operations/paired-gpio-migration.md:75` requires exact interpreter/API, file/group/device permissions, root-controlled artifacts, stopped requests, running-identity verification and existing startup/flow gates. Its rollback at `:134` requires light OFF and stopped/disabled before restoring the raw FSEL writer. A source-only script overwrite is explicitly prohibited.
- **Evidence wording remains bounded.** Pi/Dial docs, disabled markers and empty configuration examples consistently retain installed migration, disconnected-load acceptance and Protect/lamp/Dial gates. The runbook distinguishes register/readback evidence from contacts, valve position and the separate power supplies. Existing installed records are not represented as this candidate.
