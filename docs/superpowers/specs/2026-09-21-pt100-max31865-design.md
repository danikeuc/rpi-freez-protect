# PT100/MAX31865 Temperature Source Design

## Goal

Replace the uninstalled DS18B20 production temperature source with a three-wire
PT100/MAX31865 on Raspberry Pi SPI0 CE0 without weakening the existing
fail-safe valve policy. The CrowPanel dial correction is delivered separately
from this Hub change even when both are commissioned in one maintenance window.

## Hardware contract

- PT100, three-wire, through a MAX31865 with a verified 430 ohm reference.
- `/dev/spidev0.0`, SPI mode 1, 500 kHz, 8 bits per word.
- Three-wire compensation and the 50 Hz rejection filter are enabled.
- The MAX31865 module and terminal mapping must be visually verified before a
  definitive wiring sign-off or live valve test.
- The exact breakout must provide the MAX31865 datasheet safeguard from RTDIN+
  to BIAS (10 Mohm, or a documented equivalent that forces a disconnected
  sense lead to a detectable state). Commissioning is blocked until this is
  verified on the actual board.
- The 24 V valve supply remains disconnected through sensor commissioning.

## Architecture and authority

`Max31865TemperatureSource` implements the unchanged `TemperatureSource` port.
Production `create_app()` selects it; development simulation remains unchanged.
The Raspberry Pi `ControlService` remains the only safety and actuator authority.
The CrowPanel produces user intent and receives no PT100-specific diagnostics.

`sensor_commissioned` remains `false` after software deployment and is the only
setting that may request automatic `NORMAL`. Commissioning approval is valid
only when persisted metadata matches both the active source identity
`MAX31865_PT100_SPI0_CE0` and the exact settings version that granted approval.
The first production startup after source replacement clears any inherited
approval; a rollback that changes settings without maintaining that binding is
also rejected on redeployment. An uncommissioned adapter may report a healthy
raw temperature to the administrator status so that commissioning is possible,
while the policy must still command `DRAIN` with `sensor_pending`.

The DS18B20 adapter remains in the repository as a rollback artifact but is no
longer selected in the production composition root. `sensor_device_id` remains
a deprecated, accepted, and persisted API field for backwards compatibility; it
is ignored by the MAX31865 source.

## One-shot sample sequence

One SPI device is opened for the complete sample and closed afterwards:

1. Clear any latched fault with three-wire and 50 Hz bits configured.
2. Enable VBIAS and wait at least 10 ms for settling.
3. Initiate the automatic master fault-detection cycle, poll its control bits
   with a bounded timeout, and read the fault register.
4. Reject any reported cable/reference fault, otherwise wait another 10 ms for
   the input network to settle after the fault cycle.
   Automatic mode is valid only when the module's verified input-filter RC time
   constant is at most 100 microseconds. A module above that limit requires the
   datasheet's manual fault-cycle timing and is not commissioned with this
   adapter.
5. Trigger a one-shot conversion and wait 66 ms.
6. Read both RTD registers in one transfer.
7. If the RTD fault bit is set, read and retain the fault register for diagnosis.
8. Disable VBIAS in a `finally` path, including read or conversion failures.
9. Close the SPI device.

The 15-bit RTD ratio uses `Rref=430.0 ohm`. Conversion follows IEC 60751
Callendar-Van Dusen constants for PT100. The negative branch is solved on
`-200..0 degC`; accepted application readings are limited to `-50..120 degC`.

## Fail-safe behavior

| Condition | Reading health | Controller result |
|---|---|---|
| Finite PT100 result within `-50..120 degC` | `HEALTHY` | Policy continues; commissioning still gates `NORMAL` |
| Fault bit, short transfer, impossible ratio, non-finite or out-of-range result | `INVALID` | `FROST_PROTECTION` / `DRAIN` |
| SPI open, transfer, or OS error | `STALE` | `FROST_PROTECTION` / `DRAIN` |
| `sensor_commissioned=false` with any reading | reading is preserved | `sensor_pending` / `DRAIN` |

A failed read never reuses an earlier value. MAX31865 fault flags are available
in Hub diagnostics, not in the CrowPanel device contract.

## Deployment and compatibility

- Pin production dependency `spidev>=3.8,<4` on Linux.
- The service uses `SupplementaryGroups=spi`; it is never run as root for SPI.
- Keep the existing Hub API, relay boundary, tokens, and settings version rules.
- Validate the unit, restart the service, and verify `/dev/spidev0.0` access as
  `freezeprotect` before commissioning.

## Commissioning gates

1. Verify the module revision, 430 ohm reference marking, three-wire jumper,
   PT100 terminal mapping, logic voltage, common ground, strain relief, and the
   10 Mohm RTDIN+-to-BIAS disconnect safeguard (or documented equivalent).
2. Verify `/dev/spidev0.0` and read/write access for `freezeprotect`.
3. Deploy with `sensor_commissioned=false`; prove `sensor_pending` and `DRAIN`.
4. Record at least three stable room-temperature readings within 1.0 degC of an
   independent reference.
5. Check near the safety region with a controlled reference around 0 degC and a
   second point around 8..10 degC; record the observed error.
6. Attach the probe to the cold-water pipe with good thermal contact below the
   insulation and repeat the stability check.
7. Exercise each sensor lead disconnected individually, short/fault, restart,
   and stale/error behavior with the 24 V valve supply disconnected. Every case
   must return a non-healthy reading and remain in `DRAIN`.
8. Only after all gates pass, set `sensor_commissioned=true`; any live valve test
   requires a separately bounded test and physical position observation.

## Verification requirements

Automated tests cover the register sequence, VBIAS cleanup on every path,
positive and negative conversion, fault-bit decoding, impossible ratios, short
transfers, SPI failures, production selection, legacy settings compatibility,
display contract isolation, and the policy's uncommissioned/unhealthy `DRAIN`.
