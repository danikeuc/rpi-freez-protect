# v1.4.0 — Independent light and controller reliability

## Included

- Independent GPIO21 light, authenticated UniFi Protect person events and Dial/admin controls, settings and history.
- Timed AUTO, explicit manual modes, and a 900-second camera cooldown after manual ON expires before returning to AUTO.
- Kernel-owned paired GPIO20/26 coexistence, bounded OFF recovery and sanitized fault diagnostics.
- Continuous DietPi time synchronization and bounded controller startup time readiness.

## Verification and deployment

1,176 Python tests, Ruff and strict typing pass. Node-RED ingress tests cover authentication, replay identity, bounds and cancellation. Existing operator receipts document staged lighting, cooldown, recovery, diagnostic and time-sync installations; this release consolidates their source. Publishing the package does not upgrade the installed Pi automatically.

Light navigation acceptance belongs to the companion Dial artifact. GPIO readback is not physical lamp or valve confirmation. Cold-boot acceptance after the time-sync change remains untested. Historical shower HTTP 503 root cause is unresolved. The owner accepted that a light may remain ON after executor crash/hang; this is not a guaranteed fail-OFF output. No new physical load/valve test or OS/kernel upgrade is claimed.

Installations and recovery must follow deployment/WORKSTATION_CODEX_COMMISSIONING.md. The baseline-bound historical maintenance packages are not generic v1.4.0 upgrade commands. Existing runtime credentials and data must be preserved.

## Post-release operating notes — 2026-10-18

The installed light gateway uses a dedicated private-LAN listener at `http://<Pi-LAN-IP>:8082`; port 8081 serves the shower/weather gateway. The Dial's independent light connection requires its own display and settings credentials. The original Dial operations guide incorrectly used 8081 as an example.

The time-ready gate may time out before the first network synchronization. In that case the controllers remain stopped even after time later synchronizes. This is the intended fail-closed result, not evidence of a bad light token. The [time-sync runbook](../../deployment/time-sync/README.md#late-synchronization-after-a-failed-startup-gate) gives the bounded, disconnected-load, root-console recovery. Starting the time-ready unit alone does not start either controller.

These notes correct the connection and recovery instructions. They do not change the published v1.4.0 Python artifacts, the installed Pi software, or physical acceptance evidence.
